# Responsive layout review — 2026-10-06

## สาเหตุ

1. `placeGuide` ใน `src/guide-layout.ts` กำหนด Monchhichi ที่ 136/156px และไกด์จักรวาลที่ 96/108px จึงมีสัดส่วนเล็กบนจอใหญ่ และไม่ได้เปลี่ยนตามความสูงที่ใช้ได้จริง
2. ปุ่มหลักใช้ตัวอักษร 14px; ปุ่มจบใช้ 13px; ปุ่มไปต่อในจักรวาลเป็น `text-button` 13px กฎสำหรับความสูงไม่เกิน 620px ยังลดปุ่มจบเหลือ 10px
3. `cameraPresentation` และ `CameraRig` ใช้กรอบกว้าง 4.4 หน่วยกับโมเดลหลายชนิด โดยเลข 22 กล่อง และเค้กกว้างกว่าค่านั้น บน tablet แนวตั้ง 768×1024 กรอบโมเดลช่วงพักบางฉากจึงล้นซ้ายและขวา

## การแก้ไข

- ขนาดไกด์ใช้ความสูงและความกว้างจอร่วมกับขอบเขตขั้นต่ำ/สูงสุด ขยายขึ้นบน tablet/desktop แต่คงขนาดเล็กกว่าในจักรวาลและเมื่อเปิดการ์ด
- ปุ่มหลักใช้ตัวอักษร 16–20px ความสูงขั้นต่ำ 52px และขนาดตามพื้นที่ โดยปุ่มไปเซอร์ไพรส์สุดท้ายในจักรวาลใช้รูปแบบปุ่มหลักเดียวกับฉากอื่น
- กฎขนาดปุ่มที่เป็นส่วนกลางป้องกันกฎจอเตี้ยและฉากจบลดตัวอักษรลงอีก
- `presentationSpan` กำหนดกรอบตามโมเดล และใช้ร่วมกันทั้งกล้องช่วงเปลี่ยนฉากและกล้องที่จัดเฟรมหลัง resize กล่องปลดล็อคมีกรอบกว้างกว่าเพื่อรองรับการขยายและแง้มฝา
- จดหมายใช้ตัวอักษร 16–18px พร้อมพื้นที่อ่านที่เลื่อนได้เมื่อความสูงไม่พอ; tablet แนวตั้งแยกพื้นที่ไกด์ด้านบนจากพื้นผิวอ่าน
- ใช้ CSS เดิมและคงลำดับเรื่องราวเดิม การจัดเฟรมกาแล็กซีและระบบเสียงไม่ได้เปลี่ยน

## การตรวจสอบ

- ก่อนแก้: 90 layout จาก 15 สถานะ ที่ 6 ขนาดจอ เก็บใน `responsive-layout-before.json`
- เว็บตัวอย่างหลังแก้: 150 layout จาก 15 สถานะ ที่ 320×740, 375×812, 414×896, 768×1024, 1024×768, 1280×720, 1440×900, 1920×1080, 2560×1440 และ 1280×580
- ตรวจปุ่มหลัก 50 layout: ตัวอักษรอย่างน้อย 16px, ความสูงอย่างน้อย 52px, ปุ่มอยู่ใน viewport
- ไกด์อยู่ใน viewport และไม่ซ้อนพื้นที่ปุ่มปิดการ์ด; ไม่มี horizontal overflow, JavaScript error หรือ HTTP failure ใน matrix นี้
- หลัง matrix ปรับกรอบกล่องปลดล็อคแนวตั้งเพิ่มเติม แล้วทดสอบโปรเจคจริงที่ `http://127.0.0.1:5173/` เปิดกล่องและเป่าเค้กด้วยแอนิเมชันปกติ ตรวจภาพกล่อง เค้ก และเลข 22 ที่ 768×1024
- เดินต่อจนครบ 7 part ด้วยปุ่มลดการเคลื่อนไหว ตรวจจดหมาย การเปิด/ปิดการ์ด การให้หัวใจ ฉากจบ และการเปลี่ยนขนาดระหว่าง tablet/desktop/จอเตี้ย
- ตรวจด้วย `elementFromPoint` ว่าปุ่มหลักและปุ่มปิดที่ทดสอบไม่ถูกชั้นอื่นบัง
- TypeScript และ production build ผ่าน

ผล matrix เก็บใน `responsive-layout-qa.json` และ `responsive-layout-validation.json`; ผลโปรเจคจริงเก็บใน `responsive-layout-actual.json` พร้อมภาพ `responsive-*.png` การตรวจ 150 layout ใช้โหมดลดการเคลื่อนไหวเพื่อวัดขนาดช่วงพัก; การตรวจแอนิเมชันปกติครอบคลุมช่วงเปิดกล่อง → เค้ก → 22 บน tablet แนวตั้ง

## เหตุที่ปัญหาเดิมผ่านการตรวจครั้งก่อน

การตรวจครั้งก่อนเน้นไม่ให้ไกด์ทับเนื้อหาและปุ่มปิด จึงกำหนดไกด์ให้เล็กไว้ก่อน ขณะที่กฎ CSS จากการแก้หลายรอบทำให้ปุ่มจบและปุ่มข้อความยังใช้ขนาดเล็กอยู่ รอบนี้เพิ่มการตรวจขนาดตัวอักษร ปุ่ม และสัดส่วนไกด์ พร้อมแยกกรอบกล้องตามโมเดล
